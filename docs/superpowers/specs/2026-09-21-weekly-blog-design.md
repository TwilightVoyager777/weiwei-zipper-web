# 资讯每周一篇：设计

- 日期：2026-09-21
- 状态：设计已逐段确认，待实施计划
- 修订（2026-09-21）：排期时区从北京时间改为美西时间（站长在美西），见 3.2、3.4、7。
- 范围：`/blog`（导航显示为「资讯」）

## 1. 目标与非目标

**目标**
- 资讯栏目每周一上线一篇和拉链相关的文章，5 种语言同时上线。
- 文章成批写、成批审：第一批 4 篇（校准用），之后每批 8 篇。
- 审过之后不需要任何人工操作，到日期自动上线。
- 排期快用完时主动提醒，避免节奏在某一周悄悄断掉。

**非目标**
- 不做后台/CMS，文章仍是仓库里的 markdown。
- 不改文章页的路由方式，`dynamicParams = false` 保持不动（这是修软 404 的设置）。
- 不引入具名作者，作者仍为公司。
- 不公开「按询盘沟通」的公司细节（见 §4.2）。

## 2. 已确认的决策

| 决策 | 选择 |
|---|---|
| 上线方式 | 一次写一批、审一次、按日期自动放出 |
| 频率 | 每周一篇，周一上线 |
| 批量 | 第一批 4 篇（试一个月）；之后每批 8 篇 |
| 发布机制 | GitHub Actions 每周一触发 Vercel 重建 |
| 审稿 | 在 Vercel 分支预览上读中文版，改完再合并 |
| 队列提醒 | 剩 1 篇时自动开 GitHub Issue |

## 3. 发布机制

### 3.1 日期即上线日

文章 frontmatter 的 `date`（`YYYY-MM-DD`）就是它上线的那个周一。同一篇在 5 个语言里的 `date` 必须相同。

### 3.2 站点只显示到期的文章

`src/site-data/blog-posts.ts` 的 `getBlogSlugs()` 是资讯列表、sitemap、文章页 `generateStaticParams`、结构化数据的共同入口。在这里加过滤：

- 只保留 `date <= 今天` 的文章，「今天」按 **America/Los_Angeles**（美西时间）计算。Vercel 构建在 UTC，不换算的话美西周日傍晚之后的构建会把周一的文章提前放出。
- 以下情况不过滤（显示全部排期文章）：
  - `VERCEL_ENV === 'preview'`（Vercel 分支预览，审稿用）
  - `BLOG_SHOW_SCHEDULED === '1'`（本地查看排期文章用）
- 正式站和本地 `next start` 默认隐藏未到期文章。未到期文章的网址返回真正的 404。

已核实：`src/` 里所有引用文章的地方（资讯列表、文章页、sitemap）都经过这一个入口，没有写死的 slug。

**例外：`public/llms.txt` 是手写的静态文件**，逐条列了现有 5 篇文章。新文章不会自动出现；提前写进去又会指向未上线的 404。改为 `src/app/llms.txt/route.ts` 构建时生成（`dynamic = 'force-static'`），非文章部分原样保留，文章列表取自同一入口。删除 `public/llms.txt` 以免与路由冲突。每周重建时它随之更新。

### 3.3 构建期校验

在同一模块加载时校验，任一条失败即抛错，`next build` 失败，Vercel 保留上一次部署（正式站不受影响）：

1. 每个 `content/blog/en/*.md` 在 `zh / es / ru / ar` 下都有同名文件。现有逻辑是缺失时回退到英文，会让 `/ar/blog/xxx` 显示英文。
2. 同一篇的 5 个语言 `date` 一致，且格式为 `YYYY-MM-DD`。
3. 文章内链到 `/blog/<slug>` 的目标必须存在，且目标的 `date` 不晚于本文 `date`。否则本文上线时那个链接是 404。

### 3.4 每周重建

新增 `.github/workflows/weekly-publish.yml`：

- 触发：`cron: '30 8 * * 1'` 加 `timezone: "America/Los_Angeles"`（美西时间周一 08:30，夏令时由 GitHub 自动跟随），外加 `workflow_dispatch` 允许手动运行。时区必须与 3.2 相同，`npm test` 检查。
- 两个**互相独立**的 job（一个失败不影响另一个）：
  - `rebuild`：`VERCEL_DEPLOY_HOOK` 为空则以错误退出（任务显示红色，不静默空跑）；否则 `curl -fsS -X POST` 调用。
  - `queue-check`：检出仓库，按与 3.2 相同的美西日期统计 `content/blog/en/*.md` 中 `date` 晚于今天的篇数；**≤ 1** 且没有同标题的未关闭 Issue 时，开一个标题为「资讯队列快空了」的 Issue。
  - 以每批最后一篇为例：它的前一周触发，距离第一个空档周一还有两周。
- 权限：`contents: read`、`issues: write`。只用内置 `GITHUB_TOKEN`，不推送任何提交。

### 3.5 需要站长做的一次性设置（约 3 分钟）

1. Vercel → 本项目 → Settings → Git → Deploy Hooks：名称 `weekly-publish`，分支 `master`，创建后复制网址。
2. GitHub → `weiwei-zipper-web` → Settings → Secrets and variables → Actions → New repository secret：名称 `VERCEL_DEPLOY_HOOK`，值为上一步的网址。
3. GitHub → Actions → weekly-publish → Run workflow，手动跑一次，确认 Vercel 出现一次新部署。

这一步涉及账号密钥，由站长本人操作。

排序理由：结构图解是其它文章的术语枢纽，放第一篇；落地转化型的起订量文章放最后。若审稿晚于下周一，四个日期整体顺延。

选题依据（第二轮体检 `findings/sxo.md`、`findings/geo-ai-visibility.md`）：选型类查询的 SERP 9/9 为选型指南、其中 3 个是供应商博客；码装类查询 SERP 未见独立意图（本批不做码装选题）；起订量 + 染色费段落是全站可引用性最高的内容，且竞品普遍不公开染色费口径。

备选：拉头锁定方式、对色依据（Pantone/TPX）、金属齿面颜色、到货验收清单、双开拉链的用途。

### 4.2 写作红线

1. **只写两类事实**
   - 行业通用知识：每条在发布前对照公开来源核实。
   - 已批准公开的公司数字：成品 1000 条起订、可混色、单色低于 2000 条每色 150 元染色费、打样约 3 天、确认后大货约 10 天、码装另行报价、3/5/8 号约 3/5/8 毫米、1992 年起经营、义乌国际商贸城三区摊位。
2. **按询盘沟通的细节不写成公司事实**：包装箱规、常备拉头类型与默认款、卷长、带宽、对色依据与常备色数、成品长度区间、混色单色下限。文章可以解释概念，涉及公司的具体做法一律写「按项目确认」。
3. 不写认证、客户名称、客户评价、编造的数据或案例；不点名、不评价竞品。
4. 作者为公司。
5. 每篇至少链到 2 个产品/品类页和 `/quote`；只能链到上线日不晚于本文的文章（构建期强制，见 §3.3）。
6. 英文 600–900 词，美式拼写（与全站一致）；结构同现有文章：首段直接回答问题 → H2 分节 → 简短的询价引导。
7. 五种语言：总控写中英文；西/俄/阿由翻译代理完成，术语锁定站内既有用词；总控在合并前核对数字、重音与术语。

## 5. 审稿流程

1. 在分支 `blog/batch-N` 上写完一批，本地构建与校验通过后推送；Vercel 自动生成分支预览（预览默认需登录 Vercel 才能访问）。
2. 站长在预览上读中文版，在对话里提修改意见；总控把修改同步到 5 个语言。
3. 站长确认后合并到 `master`。合并本身不上线任何文章，各篇等到自己的周一。
4. 校准批的反馈整理成文风规则，写进 `content/blog/STYLE.md`，后续批次遵循。

## 6. 异常与回滚

| 情况 | 结果 | 处理 |
|---|---|---|
| 某周重建失败 | 当周文章晚到 | 下次重建自动补上（按日期判断，不会丢） |
| `VERCEL_DEPLOY_HOOK` 未配置 | 任务红色失败 | 按 §3.5 配置 |
| 构建期校验失败 | 部署失败，正式站保持上一版 | 按报错修正文章后重新推送 |
| 公开仓库 60 天无活动 | GitHub 自动停用定时任务并发邮件 | 在 Actions 页面重新启用；正常按批合并不会触发 |
| 需要撤下某篇 | — | 删文件或把 `date` 改到未来，推送即可（重建后 404） |

## 7. 验证

- 本地：把一篇文章日期设为未来 → `next build && next start` 下该文 404、不在列表和 sitemap 中；设为今天 → 出现；`BLOG_SHOW_SCHEDULED=1` → 未来文章可见。
- 校验：分别构造「缺一个语言」「日期不一致」「链接到更晚的文章」三种情况，确认 `next build` 失败且报错指明文件。
- 时区：在美西午夜前后构造边界用例（夏令时 UTC 07:00、冬令时 UTC 08:00），确认按美西时间判定。
- `llms.txt`：改造后与原文件逐行对比，非文章部分一字不差；未到期文章不出现，到期后出现。
- 工作流：站长完成 §3.5 后手动运行一次，确认 Vercel 出现新部署；Issue 逻辑用 `workflow_dispatch` 在队列 ≤ 1 的状态下验证一次。
- 每批合并前：全量重爬回归，核心零指标（canonical / hreflang / JSON-LD / 孤儿页）保持为 0。
